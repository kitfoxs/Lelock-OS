# Authority, privacy and honest limits

## YOLO is real and scoped

SAFE asks before an effect. TRUSTED executes declared standing grants. YOLO
executes all currently granted capabilities without another per-action prompt.
The sidecar and file tools are not fictional actions. Mode selection, exact
capabilities and configuration are operator routes, never a character-card
instruction. Host execution additionally requires gateway startup with
`--allow-host-exec` and a per-entity `process.run` grant.

For Antigravity, native risk acknowledgement is required because its unmodified
runtime has its own built-in tools. Native prompt bypass requires explicit
`native_yolo` as well as Lelock YOLO. The broker cannot contain a native runtime
that can directly access the host. Do not represent workspace selection,
reduced environment or a prompt instruction as an OS security sandbox.

The Codex adapter requests a read-only native sandbox and disables native shell,
unified execution, implicit Skill/MCP installation and web search, so enabled
Lelock tools are the intended effect path. The actual installed binary must be
checked for these settings. Unsupported native requests are rejected instead
of auto-approved. Configuration intent is not independent security certification.

## Pairing and local service

Only IPv4 loopback is supported. Exact Host and approved Origin checks plus
bearer credentials protect the gateway. Pairing code use is single-shot, expires,
and rate-limited by failed attempts. Agent and operator tokens are distinct.
Native MCP tokens are scoped to one actor and one turn and cannot approve actions.
Provider OAuth tokens are never copied into the browser or card files.

The extension holds both gateway roles in its own browser context for the operator
panel. Other scripts/extensions with the same origin are consequently trusted;
separate token strings do not sandbox mutually hostile same-origin JavaScript.
Do not expose this developer service with a public tunnel. Tauri WebView origins,
HTTPS-hosted remote Tavern clients, mobile networking, TLS/OAuth multiuser hosting
and cross-machine pairing are separate work items, not enabled by wildcard CORS.

## Data ownership

The registry and turn ledger are private plaintext operational state, not a new
semantic memory system. Selected chat history is sent to the selected provider.
Local storage does not make cloud inference local. The initial Account Chat
history limit is 200 messages / 300 KB; it fails visibly rather than silently
truncating identity or inventing compression.

MemPalace remains the sole semantic authority. The gateway opens a new owned
Palace home only when enabled, uses the actual legacy transport and readback,
and never mines Kit's private Palace by default. A fresh generic fixture is used
for acceptance. Attaching an existing private entity requires a reviewed migration,
not an automatic scan of all user folders.

Native agy owns its login files under the normal native home; CODEX_HOME is
separate for the gateway. Neither is uploaded or included in exports. Do not
collect credentials in support logs. A host process running as the same OS user
can potentially access accessible state and tokens; receipt files are not proof
against that same user. Hashes detect accidental modification, not authorship.

## Failure and restart

Tool request IDs include the native turn scope. Same-ID changed payloads are
refused. Completed results can be returned without repeating an effect. Pending
approvals require an exact digest. Tool errors, incomplete exit receipts, partial
computer actions and disconnections do not become successful chat claims.
The turn ledger marks interrupted work for review; it does not replay effects
automatically after restart.

A schedule is tied to an expiring session. Permission changes or gateway restart
invalidate its old authority. Host process cancellation and remote computer stop
are best-effort boundaries with explicit uncertainty, not a universal rollback.
The provider may have native work that must be stopped in its own interface.
No claim is made of exactly-once arbitrary remote execution.

## Resource limits

Broker action count, elapsed time, output sizes and native turn deadlines are
bounded. Native usage data and Codex quota are shown where available. A coherent
cross-provider token/dollar reservation ledger is not implemented. Provider
subscription caps, optional extra-usage billing, and native account policy still
apply. There is no automatic API fallback, account purchase or paid-resource
provisioning in these installers or offline tests.

Pulse is off unless the gateway is launched with `--enable-pulse`. It uses a
local inbox and quiet hours, not external messages or always-on recording.
Scheduled inference is actual account use when enabled; short leases and explicit
tasks are intentional. The test fixtures are deterministic peers, never represented
as real models or background companions.
